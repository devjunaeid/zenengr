# US-053 — Tenant admin manages per-tenant SMTP for outgoing email

## Story

As a tenant admin, I want to configure my own SMTP server for all outgoing email (invites, password reset, email verification, comment notifications) so my tenant's email is sent through my provider with a stored, encrypted password that is never exposed in API responses.

## Acceptance criteria

- [x] Save SMTP config including all three security modes (none/starttls/ssl). (FR-13.1, FR-13.2)
- [x] Password never returned — API exposes `has_password` only. (FR-13.1, FR-13.2)
- [x] Update without resending password keeps existing password. (FR-13.2)
- [x] Test email works and reports errors. (FR-13.3)
- [x] Configured SMTP used for invites/reset/verify/comments. (FR-13.4, FR-13.5)
- [x] Disabled/failed SMTP falls back without breaking actions; failure writes audit email.send_failed. (FR-13.6)
