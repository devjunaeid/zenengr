# US-047 — Admin realm authentication (JWT login, password hashing, /me)

## Story

As an Admin user (Super Admin or Tenant Admin/Manager/Employee), I want to log in via a dedicated auth endpoint with my email and password, receive a JWT token scoped to the admin realm, and retrieve my own profile via a /me endpoint, so I can access admin portal features.

## Acceptance criteria

1. `AdminUser` SQLAlchemy model with hashed passwords (bcrypt), email unique, status (active/deactivated), FK to tenant. (FR-4.3)
2. `POST /api/v1/auth/login` accepts email + password, returns JWT token with admin realm scope.
3. `GET /api/v1/auth/me` returns current admin user profile (requires valid JWT).
4. Deactivated admin users are rejected at login. (FR-4.11)
5. Tenants with status `Suspended` or `Cancelled` reject login at the auth layer. (FR-1.3, FR-4.6 realm separation)
6. JWT contains sub (user_id), tenant_id, role, realm ("admin"), exp.
7. Password hashing via bcrypt (passlib).
