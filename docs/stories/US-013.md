# US-013 — Tenant Admin edits role / deactivates / reactivates staff user (last-admin guard FR-4.14)

## Story

As a Tenant Admin, I want to edit roles, deactivate, or reactivate staff users so I can manage team changes, while the system prevents me from removing the last remaining Admin.

## Acceptance criteria

1. Tenant Admin can edit an existing admin user's role at any time. (FR-4.10)
2. Role changes take effect on next API request (no re-login required). (FR-4.10)
3. Tenant Admin can deactivate an admin user; deactivated user immediately loses portal access. (FR-4.11)
4. Historical records (comments, actions) remain attributed to the deactivated user. (FR-4.4, FR-4.11)
5. Tenant Admin cannot deactivate or change role of the tenant's last remaining Admin. (FR-4.14, AC-5)
6. Deactivated user can be reactivated by Tenant Admin. (FR-4.11)
7. Deactivation/reactivation is recorded in the audit trail. (FR-4.13)
