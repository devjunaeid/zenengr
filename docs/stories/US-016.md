# US-016 — Tenant Admin/Manager creates a Client User with credentials and manages access

## Story

As a Tenant Admin or Manager, I want to create a Client User (client's employee) directly with email + password as the primary billing contact so they can log into the Client Portal to view their projects and invoices, and change their password or revoke/restore access when needed.

## Acceptance criteria

- [x] Tenant Admin/Manager creates a Client with `client_user_email` + password, creating the primary billing contact as an active Client User. (FR-4.7, AC-8)
- [x] Client User logs into the separate Client Portal with the credentials set at creation. (FR-4.6, AC-8)
- [x] Client User sees only their own Client's projects, invoices, transactions, and comments. (FR-4.6, FR-4.8)
- [x] Tenant Admin/Manager can change the Client User's password. (FR-4.7)
- [x] Tenant Admin/Manager can revoke and restore a Client User's portal access. (FR-4.7)
- [x] Revoked Client User cannot log into Client Portal; restored user can. (AC-9)
- [x] Client User cannot see other clients' data, other tenants, or internal-only comments. (FR-4.8, AC-9)
- [x] Invite-based Client User onboarding removed from UI; invite endpoints dormant. (US-016)
