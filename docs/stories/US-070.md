# US-070 - Lazy Loading Tab Data on Demand for Project, Client, and Portal Views

## User Story

As a **user (staff member or client portal user)**,
I want **multi-tab pages (Project Details, Client Details, and Client Portal Projects) to load instantly without waiting for all tab data upfront**,
so that **I can start working immediately and only fetch heavy datasets (ledgers, invoices, files, team members, activity logs) when I actually open those tabs**.

## Acceptance Criteria

1. **Staff Project Details (`/app/projects/[id]`):**
   - Initial page route (`+page.js`) only fetches core project, client, and overview summary data needed for the default Overview tab.
   - Upfront fetching of `users` (100 rows), `ledger` (all transactions), `invoices` (100 rows), `files` (100 files), `folderTree`, and `projectRoles` is removed.
   - When a user clicks the **Ledger**, **Invoices**, **Files**, or **Team** tab for the first time, an inline loading state is displayed while fetching that tab's data.
   - Resolved tab data is cached in component state so switching back to previously loaded tabs is instant (0ms delay, no re-fetching).
   - Fast refresh operations (`refreshFinancials`) re-query the active dataset without re-triggering monolithic multi-request blocking.
2. **Staff Client Details (`/app/clients/[id]`):**
   - Initial page route (`+page.js`) does not block on `notes`, `activity`, and `client ledger`.
   - Notes, Activity, and Financials tabs load on-demand upon first tab selection and cache their results.
3. **Client Portal Project View (`/client/projects/[id]`):**
   - Initial page route (`+page.js`) loads only the project overview.
   - The Files and Financials tabs load on-demand on first click and cache results.
4. Clean skeletons/spinners are rendered during on-demand tab fetches without jarring layout shifts.
