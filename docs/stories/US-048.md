# US-048 — Storage abstraction: local today, S3-compatible switchable

## Story

As a platform engineer, I want object storage behind a pluggable backend so the platform can run on a local filesystem today and switch to an S3-compatible provider (MinIO/R2/S3) via config without code changes.

## Acceptance criteria

- [x] Pluggable backend interface (`put`/`get`/`delete`/`url`/`exists`). (FR-12.1)
- [x] Local backend stores files under a configured directory. (FR-12.1)
- [x] S3-compatible backend via boto3 with `endpoint_url` support. (FR-12.1)
- [x] Switching backend = config change only; no code edits. (FR-12.1)
- [x] Storage keys namespaced per tenant. (FR-12.2)
- [x] Public namespace only for branding. (FR-12.2)
- [x] Migration/backfill tool transfers existing data. (FR-12.8)
