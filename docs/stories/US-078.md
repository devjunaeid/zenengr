# US-078 - Flexible, mistake-tolerant and auditable corrections (ADR-004)

## Story

As a non-technical admin who sometimes makes mistakes,
I want to edit or remove any payment, adjustment or purchase easily, and undo or restore it if I was wrong,
So that fixing errors is effortless while the company still keeps a complete history for audit.

## Acceptance Criteria

- **AC-078.1:** Payments (amount, date, method, reference, notes, allocations), adjustments and purchases are editable; each edit stores before/after values.
- **AC-078.2:** Delete is a soft delete (void) with an optional reason; the row stays visible, struck through, and is excluded from totals.
- **AC-078.3:** An admin can restore a voided payment/adjustment in one click; totals recompute.
- **AC-078.4:** After create/edit/delete an Undo toast (~8 s) reverses the action.
- **AC-078.5:** Each financial record has a "History" panel listing who changed what and when.
- **AC-078.6:** Purchase entry create/update/delete are audited (`purchase.created|updated|deleted`).
- **AC-078.7:** Unusual but valid input (e.g. payment larger than due) shows a friendly warning, not an error.
