# US-071 - Lean API Queries, Default Scoped Payloads & On-Demand Extensions

## User Story

As a **developer and system user**,
I want **API endpoints to execute minimal database queries and return lean, bare-minimum payloads by default while allowing on-demand extensions via query parameters**,
so that **network latency, server memory, and database overhead remain low as data volumes grow**.

## Acceptance Criteria

1. Endpoints provide bare-minimum core payloads by default; expensive nested relationships (such as full sub-collections or rollups) are only computed or included when requested or necessary.
2. High-frequency endpoints (e.g. `/projects/{id}`, `/clients/{id}`, `/invoices`, `/files`) avoid N+1 queries and avoid computing unused joins during default list/detail views.
3. Pagination limits and projection rules prevent runaway query sizes on initial route visits.
4. Response schemas are strictly typed and backwards-compatible with existing consumers.
