# US-076 - Single source of truth for client payments and advances

## Story

As a company admin,
I want every client payment recorded exactly once and optionally allocated to invoices,
So that Paid, Due and Advance are always correct and I can see which invoices each payment settled.

## Acceptance Criteria

- **AC-076.1:** A `payments` table stores every receipt/refund; invoice `transactions` are allocations linked by `payment_id`.
- **AC-076.2:** Two payments with the same amount and date both count toward project Paid (no heuristic dedup).
- **AC-076.3:** Allocations of a payment can never exceed its amount; the unallocated remainder is shown as Advance.
- **AC-076.4:** Overpaying an invoice leaves the excess unallocated; it can be allocated to another invoice of the same client.
- **AC-076.5:** Recording a payment from the project ledger or from an invoice uses the same service and produces the same records.
- **AC-076.6:** Existing data is migrated with a dry-run reconciliation report before commit; original rows retained.
